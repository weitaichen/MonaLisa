## 摘要（繁體中文）

v0.4 一次發布六項功能，依序是：選臉／選人 → 調節＋一鍵質感 → 裁切／旋轉／翻轉＋原解析度／PNG 匯出 → 膚質工具 → 臉型細項＋美妝擴充 → 推臉筆＋恢復筆。六項都完成後，版本才升到 0.4.0。
參數分成兩層：「整張照片」一層（美白、銳化、濾鏡、調節、質感、增高、長腿、背景保護、裁切、祛痘點、推臉筆筆畫），以及「每個人物」一層（磨皮、紅潤、美型、美妝、膚質、局部美體）。復原（↶ ↷）、預設、重置、存檔都以這兩層為單位運作。
所有位置資料（臉、身體、遮罩、位移場、筆畫）都存成原圖方向的正規化座標。裁切和旋轉是最後才套用的幾何變換，所以旋轉照片不必重新偵測。
引擎仍然只對原圖取樣一次。多張臉的位移在原圖座標裡算好後相加，再和美體位移場、推臉筆位移場合併，最後才套上裁切。原解析度匯出改用分塊算圖，以避開 iPhone 的記憶體上限。
「最近編輯」的紀錄升級到第 2 版：會存下偵測結果和每個人物的參數，重新開檔時不必重跑偵測。舊紀錄會在讀取時自動轉換。
動工前先做 Phase 0 量測：多臉偵測要多久、GPU 有哪些上限、記憶體夠不夠。量測結果決定臉數上限、分塊大小，以及量測不理想時要退回哪個方案。

## 1. Goal and user-visible behaviour

### 1.1 What v0.4 is

v0.4 turns the single-face, single-look editor into a per-person portrait editor. It also adds the adjustments and output-quality features that GAP ranks P0 or P1. Everything still runs on the device: CSP stays `connect-src 'self'`, MediaPipe stays pinned at 0.10.35, there is one FaceLandmarker instance, and there is no cloud and no telemetry.

| # | Feature | User-visible result | Where |
|---|---|---|---|
| 1 | **選臉／選人** | A group photo shows a box on each face and a strip 「全部｜1｜2｜3…」. Each person keeps their own 磨皮, 紅潤, 美型, 美妝 and local 美體 values. Face edits and body edits always land on the same person. In the camera, the user taps a face to choose who gets beautified. | Editor and camera |
| 2 | **調節**, **一鍵質感** | A new 調節 tab with 亮度, 曝光, 對比, 高光, 陰影, 色溫, 色調, 飽和, 鮮艷度, 褪色, 顆粒 and 暗角. In 一鍵, a 「質感」 part offers 膠片, CCD, 直閃, 藍調 and 電影感. Both work live in the camera. | Editor and camera |
| 3 | **裁切／旋轉／翻轉**, **原解析度＋PNG** | A 裁切 tab with free and fixed ratios, 90° rotation, 拉直 and horizontal flip. 儲存 exports at the photo's own resolution (long edge up to 4096) as JPEG or PNG. | Editor |
| 4 | **膚質** | New items in 美膚: 祛痘 (tap a spot to remove it), 勻膚, 膚色, 黑眼圈, 法令紋, 白牙 and 亮眼. | Editor |
| 5 | **臉型細項**, **美妝擴充** | New 美型 items: 鼻翼, 山根, 嘴高, 太陽穴, 髮際線 and 下頜線, plus 左右分開 to set the two sides of the face separately. New 美妝 parts: 眉毛, 眼影, 眼線, 睫毛, 臥蠶, 修容, 高光 and 美瞳. | Editor and camera |
| 6 | **推臉筆＋恢復筆** | Manual liquify on the face and the body. Strokes are saved with the photo and can be undone with ↶. | Editor |

**Invariant for every step:** a photo with one person, edited with v0.3 items only, renders the same as in v0.3. Each channel may differ by at most 1/255; the parity goldens in §8.4 check this. Existing tests keep their assertions, except the five intended changes the step-1 spec lists in §8.5 (for example `numPoses` 2 → 4). When a signature changes, the test is ported mechanically in the same commit.

### 2.2 Persons: boxes, strip and 全部

- **Person strip** (`src/ui/components/PersonStrip.tsx`, new). It is a row of 52 pt between the canvas stage and the slider row. It exists only when the photo has **≥ 2 selectable persons**, and it then stays mounted on every tab so the canvas never jumps. Chips are 44 × 44 pt: 「全部」 first, then one face thumbnail per person, each with its number. Persons are numbered left to right by the face box (or the body box for a body-only person) when the person list is first built; persons found later are appended, so a number never changes (step-1 spec §2.1, §11 Q1). The selected chip has a 1 px accent outline (DS §7.1). On photo-level tabs (濾鏡, 調節, 裁切, 一鍵/質感) the chips are dimmed, not selectable, and a caption reads 「整張照片」.
- **Face boxes** (`src/ui/components/FaceBoxes.tsx`, new). These are drawn inside `.zoom-layer` and are **not** buttons (`pointer-events: none`): zoomPan drops every pointer that starts on a button (`zoomPan.ts:82`), so button boxes would block pinch, pan and double-tap on faces. Taps reach zoomPan's `onTap` (below); the chips are the accessible control. They show on person-level tabs when ≥ 2 persons exist. Each box is drawn as four corner brackets, 2 px at any zoom, on the face box padded by 15 % (step-1 spec §2.1): unselected in `--text-2` at 60 % opacity, selected in `--accent`, each with its number badge. They are hidden while a slider is dragged, while 按住對比 is held, and in 祛痘, 推臉筆 and 裁切 modes.
- **Tapping the photo** selects a person. zoomPan gains `onTap(uv)`: a single tap that moved less than 8 px and was not on a button (`zoomPan.ts:103-113`). The tap is mapped V→O (§3.5) and through the backward map without the face chains (the liquify field from step 6, then the body field), then hit-tested against the face boxes on every person-level tab and, in the 美體 tab when no face was hit, against the cached person masks; the higher mask value wins where masks overlap. Without masks, the test uses the pose bounding boxes.
- **Selection.** The default is the primary person (§3.6). The selection is view state: it is kept per photo, it is not an undo step, it is not persisted, and it is not part of the output key. The module-level `lastSel` (`Editor.tsx:66`) keeps only the panel tab selection.
- **全部.** Dragging a slider writes **that item's** absolute value to every person the item applies to; every other item keeps each person's own value. The slider shows the primary person's value. When the persons differ, the slider label gets a small 「各人不同」. Tapping a preset, shade, 質感 or 左右分開 while 全部 is selected applies it to everyone, including persons who already match the primary: under 全部 an item shows as selected, and a tap on it is a no-op, only when every target already matches (§3.3). The first 全部 write of a session shows the toast 「已套用到全部人物」.
- **Items that do not apply** to the selected person get a strip note and are dimmed, using the existing `faceNote` pattern (`Editor.tsx:789-797`, `BeautyPanel.tsx:43`):
  - no face: 「這位人物未偵測到臉部，臉部效果不適用」
  - no body: 「這位人物未偵測到身體，僅能使用增高、長腿」

### 2.4 Camera

- **Tabs:** 一鍵 · 美膚 · 美型 · 美體 · 濾鏡 · 美妝 · 調節 (7 tabs, 51.9 pt each). 裁切 does not exist in the camera. Items marked editor-only (`live: false` in §3.1) are left out of camera strips; today that is 祛痘, every 膚質 tool and 推臉筆. The 美體 tab keeps 「美體目前僅支援照片編輯」 (`panelModel.ts:92`).
- **Choosing a face:** up to 3 faces are tracked. By default the largest face is beautified, which is today's behaviour for a single face. While ≥ 2 faces are tracked, tapping a face selects it (with one face, a tap collapses the panel as today): the tap is un-mirrored for `user` facing and hit-tested against the face boxes, and the camera then shows an accent ring around that face for 800 ms and a 6 px accent dot above it while ≥ 2 faces are tracked. A tap anywhere else still collapses the panel (`Camera.tsx:260-264`).
- **全部套用:** a floating chip at the top left of the preview, shown only while ≥ 2 faces are tracked. When on, every face gets the same look. It is off by default and is not persisted.
- The camera keeps **one look** for every face. There are no per-face settings in the camera (approved).

## 3. Architecture and data model

### 3.1 Where every parameter lives

Every `ParamId` belongs to exactly one layer. `ParamDef` (`types.ts:36-47`) gains `scope: 'photo' | 'person'`, `live: boolean` (offered in the camera) and `split?: true` (can be set per side). A unit test checks that every id has a scope, that the two layers do not overlap, and that the table below matches `PARAM_DEFS`.

| ParamId (label) | Scope | Notes | Step |
|---|---|---|---|
| `skin.smooth` 磨皮, `skin.rosy` 紅潤 | person | The strength is per face and is written into the skin mask (§4.4). **In a photo with no face** they act on all skin, as today, using the primary person's values. | 1 |

### 3.3 One lens for every edit (`src/edit/lens.ts`)

- **Person items** need a face (skin, shape, makeup, tone) or a body (local body items, also subject to `paramAvailability`).

- `panelModel.ts` (`itemsFor`, `activate`, `sliderFor`, `tabHasValue`: lines 301-561) is ported to take `(lens, sel, ctx)` instead of `BeautyParams`. `SliderBinding.apply` becomes `(lens, v) => EditState`.

### 3.4 Undo, presets, 重置, sanitize, serialization

- **Undo.** `UndoStack<EditState>` keeps its current API (`undo.ts:17-53`, default cloning, so existing tests pass) and gains:
  - an option `{ clone: false, key }`: states are stored by reference, which is safe because `EditState` is immutable;
  - `rebase(fn)`: maps every stored state. It is used when a detection adds persons, when `primaryInit` is assigned, and when a v1 entry is migrated, so undoing never brings back a state without a person who is now known.
  - The editor uses `key = editKey`, which is `stableKey` with each `Stroke.points` replaced by `Stroke.id`. Stroke arrays are therefore shared between states (one copy in memory) and never serialized for comparison.
  - The undo depth stays 50. Selection changes never push.
- **Beauty presets (原圖, 自然, 精緻, 氣色)** have a *person part* and a *photo part*:
  - Person part: every person-level face item. v0.3 items keep their v0.3 values; v0.4 items (臉型細項, new makeup, tone) are neutral in every preset (§11 Q7). Shades lip and blush.
  - Photo part: 美白, 銳化, `filterId`, `filter.amount`.
  - Presets never touch 美體, 調節, 質感, geometry, spots, strokes, `bodyProtect` or the bands (as today for 美體: `params.ts:163-181`).
  - **Apply:** the person part goes to the target persons (the selected one, or every person under 全部), with `preset = {id, amount}`. The photo part goes to `photo`, and `photo.presetLink = {id, amount}`.
  - **程度:** the person part goes to the targets. The photo part is re-applied only while `presetLink.id` equals the preset being scaled.
  - **Breaking the link:** any edit to 美白, 銳化 or 濾鏡 sets `presetLink = null`. Any person-level face-item edit sets that person's `preset = 'custom'`; body items never do (as today, `params.ts:193-200`).
  - **Matching:** the preset id a person shows is checked against the person part only (`matchesPreset`, `params.ts:307-311`, ported).
- **質感 looks** live in `photo.look`. A look is a LUT plus fixed 調節 offsets plus grain, fade and vignette (§4.4). `amount` (程度) scales the offsets and the LUT mix. The user's own 調節 values add on top in shader space, and the sliders keep showing the user's values. 「無」 clears the look. A look never changes a beauty preset, and a preset never changes the look.
- **重置** (confirmation 「確定重置全部？」 with ≥ 2 persons, today's 「確定重置？」 with one) sets `photo = defaultPhoto()` (the 自然 photo part, everything else neutral or identity, no spots, no strokes) and every person to `naturalPerson()`. `template` is kept. It is one undo step, as today (`Editor.tsx:761-769`).
- **Sanitize.** `sanitizeEditState` clamps every value to 0..1. It validates `filterId`, `look.id`, every shade and every preset id. It checks the geometry (crop inside the straightened frame, otherwise identity). It drops non-finite spots and strokes and enforces the caps (§5.3). It drops persons that are not in the detection cache, adds missing persons from `template`, and keeps a person's preset id only if the values still match it, as `params.ts:301-303` does today.
- **Serialization.** `EditState` is structured-cloneable (plain objects, numbers, `Float32Array`) and is stored in IndexedDB as it is. `CameraLook` holds no typed arrays and is stored in localStorage as JSON. The output de-dupe key `keyOf` (`Editor.tsx:68`) becomes `editKey(edit)`. The selection is not in it, because it does not change the output.

### 3.5 Coordinate spaces (decision)

| Space | Definition | Used for |
|---|---|---|
| **O** (original) | The EXIF-oriented full-resolution frame `W_O × H_O`, normalized to [0,1]², origin top left, y down. Same axes as `createImageBitmap(..., {imageOrientation: 'from-image'})` (`importer.ts:4-13`). | **Everything persisted:** landmarks, poses, masks, the body, protect and liquify fields, spots, strokes, face boxes |
| **W** (working) | O decoded at long edge 2048 (1440 on tier L) (`flows.ts:7-13`). Same normalized coordinates as O; only the scale differs. | Detection, preview, thumbnails, history `original` |
| **E** (upright edit frame) | O after `flipH`, then `quarter`: an exact, lossless permutation of the pixels | Detector input when E ≠ O, and computations that depend on which way is "up" (§4.5). Results are mapped back to O. |
| **V** (view and output) | E after `straighten` and `crop`, normalized to the crop | Canvas, overlays, export |
| **T** (tile) | A sub-rectangle of V | Tiled export (§4.6) |

**Decision: store everything in O and apply crop, rotate and flip as a final geometric transform (§4.2). Never detect on the view.**

Why:
1. Changing the geometry is then only a change to `photo.geometry`. It is cheap to undo, needs no re-detection, involves no identity churn for persons, and per-person params keep pointing at the same faces.
2. Normalized O coordinates are independent of resolution, so the 2048 preview, the tiles and the full-resolution export share every cached artifact.
3. iPhone photos arrive EXIF-oriented, so a sideways O is rare (screenshots, photos taken lying down).

**U (up frame).** O turned by whole quarter turns only, never mirrored, so that U-up equals E-up: `upQuarter(g) = flipH ? (4 − q) % 4 : q`. E = U or its mirror, so **E rows and U rows are the same rows** (step-3 spec §3.2).

**Sideways photos.** BlazeFace is unreliable on faces rotated 90°. So whenever the editor is in normal mode (on leaving the 裁切 tab, or after ↶ ↷ in another tab) while the face cache is empty, a tracker exists and `faceScans` has no entry for the current `upQuarter`, the editor runs face detection once on the U-permuted working image ("正在重新偵測臉部…") and maps the landmarks U→O exactly. It does not scan on each 旋轉 tap, so turning a photo several times stays instant (step-3 spec D12). `faceScans` records which up-frame was scanned (§3.6); a scan counts for both flip states. A cache that already has faces is never re-detected. Body detection and the selfie segmenter run on the U image of the geometry current when they first run, and their results are mapped U→O the same way (`DetectionCache.bodyScans`, §3.6).

**Directions that depend on "up".** Row bands (增高 and 長腿) and the body measure (head, neck and leg directions) are computed in **U** (step-3 spec D4): inputs are mapped O→U, the field is built on a U grid and then mapped back by an exact texel permutation with the vector components rotated. A 翻轉 therefore never rebuilds the body field (`BodyFieldMemo` keys on `upQuarter`). `heightBand` is stored in E coordinates, which have the same rows:
- a **旋轉** action (E changes by a quarter turn) clears the band in the same undo step, with the toast 「旋轉後已移除增高」;
- a **翻轉** action keeps the band (E-vertical is unchanged);
- straighten and crop do not affect E.

**View transform module** (`src/geometry/view.ts`, new, pure). It provides `oToE`, `eToO`, `eToV`, `vToE`, `oToV`, `vToO`, the same for vectors (brush deltas), `cropConstrain(geometry, oSize)`, `upQuarter`, and the action reducers `rotateLeft(g)` (旋轉, 90° counter-clockwise), `flipView(g)` and `setStraighten(g, θ)` (step-3 spec §3.3). "Flip in the view" is canonicalized: F∘R_q = R_{−q}∘F, so `flipView` gives `flipH' = !flipH`, `quarter' = (4 − q) % 4`, `θ' = −θ` and `crop.x' = 1 − crop.x − crop.w`. Every overlay (face boxes, band lines, spot markers, brush cursor, person hit-test) maps through this module. `HeightBandOverlay.tsx:232-235` (client rect → UV) becomes client → V → E.

**Live camera.** The unmirrored video frame is O, with no geometry. Mirroring happens only at present (`live.ts:124`). A capture's saved image (cropped to the ratio, mirrored per prefs) becomes the editor's O.

**Full-resolution export** re-renders from the source file decoded at the export size, with the same normalized caches (§4.6). Kernels that depend on resolution scale with the **full O short edge in output pixels** (`fullShortEdge`), never with the size of a tile or crop buffer, so 磨皮, 銳化 and 顆粒 look the same in the preview, a crop, a tile and the export.

- **Raw landmarks are cached,** not the adapted `Face`. A later adapter change (step 5 adds `Face.iris`) then needs no re-detection. The cost is 5.7 KB per face.
- **Detection limits** (`src/config/limits.ts`, new, a single file so Phase 0 results are one-line changes):
  - editor: up to **MAX_EDIT_FACES = 6** selectable faces, requested as `numFaces` = `EDIT_DETECT_FACES` = MAX_EDIT_FACES + 2 so the over-cap count is real and small background faces do not take a slot (step-1 spec A1); `numPoses` = **MAX_EDIT_BODIES = 4**. The count is sent in the same `setOptions` as the IMAGE/VIDEO switch so no extra graph rebuild happens (`tracker.ts:114-122, 338-352`);
  - `MIN_FACE_FRAC = 0.03`: a face whose box width is under 3 % of the short edge is not selectable and gets no face effects; it counts toward `dropped.tooSmall`;
  - beyond the cap, the largest boxes are kept (`dropped.overCap`).
- **Tracker contract** (`types.ts:228-243`): `detectImage(img, {maxFaces})` returns `Landmarks478[]`, and `[]` means no face. `toLandmarks` (`tracker.ts:46-57`) keeps every entry with ≥ 478 points. VIDEO mode passes `numFaces` explicitly, because options are sticky.
- **Body contract:** `BodyTracker.detect` returns `{bodies: {pose, mask, score}[]}` with every person's mask copied before `result.close()` (`bodyTracker.ts:237-252, 465-470`). `numPoses` goes from 2 to 4 (`bodyTracker.ts:292`).
- **Pairing** (`src/detect/persons.ts`, pure). The cost of a face–body pair is the mean distance between the pose nose, inner eyes and mouth corners (pose 0, 2, 5, 9, 10) and the face landmarks nose tip, eye centres and mouth corners (`pts111[46]`, `[104]`, `[105]`, `[84]`, `[90]`), divided by the face's inter-ocular distance. A pair is a candidate when the cost ≤ 0.5, the pose nose lies inside the face box padded by 10 %, and `maskCoversFace(face, mask) ≥ 0.5` when a mask exists (`faceProtectModel.ts:59-96`). Pairs are taken greedily in ascending cost, 1:1. Unpaired faces become face-only persons; unpaired bodies become body-only persons.
- **Person ids are immutable once persisted.** A person keeps its id when it gains a face or a body (the links are `PersonInfoCached.face` and `.body`), and UI numbers never derive from ids:
  - a person first built from a face takes the face's id `f<i>`; one first built from a body takes the body's id `b<j>` (new bodies get the lowest free `b<j>`);
  - while nobody is known (before the first definite answer, or in a photo with nobody), the lens edits the implicit `p0`, created from `primaryInit ?? template`. When the first persons become known, `p0`'s params move to the primary person (via `rebase`) and `p0` is removed;
  - a cache is re-detected only when it cannot serve: a 基本模式 cache (`faceScans = []`) opened with a tracker gets its faces merged in, and a corrupt or ill-fitting cache is rematched by box IoU (§5.2). Both keep the ids of the persons they match.
- **Obstacles:** faces dropped by the size filter or the cap get no effects, but their box and oval are kept so that they bound their neighbours' caps and 瘦臉 limits.
- **Primary person:** the face box area × centrality, with the same score as `selectPerson` (`bodyTracker.ts:158`). Without faces, the body box is used.
- **Head and neck anchors** of `measureBody(det, face)` (`measure.ts:192, 284-298`) receive the face **paired** with that body, or null. This fixes the latent group-photo bug.

### 4.3 N faces in one pass: uniform and texture budget

- **Face table:** one packed layout behind one shader accessor, carried either by an `RGBA32F` texture, `NEAREST` (`createTexture` defaults to LINEAR, `gl.ts:108`; a LINEAR float texture is incomplete), read with `texelFetch`, or by a std140 UBO; Phase 0 ships the faster carrier. One row per face, 96 texels wide:
  - 56 for `pts111`, 4 for `ext`, 6 for the V, narrow and chin targets plus radii;
  - 6 for strengths, with a left and a right value per split item;
  - 1 for the box, 1 for the cap, 1 for the protect window;
  - 21 spare (texels 75–95), all used by step 5 (step-5 spec §4.4); the row is then full, and a later per-face item needs a wider row (128 texels still fit the UBO: 6 × 128 × 16 B = 12.3 KB).

  The reshape program's uniform count is then **≤ 32 vectors for any N** (today about 146 for one face: `uPts[111]`, `uExt[8]`, `uVT[6]`, `uNT[4]` plus about 17 more, `reshape.ts:217-233`). The loop is `for (int f = 0; f < MAX_RENDER_FACES; f++) { if (f >= uCount) break; … }` with a per-face box test.
- **Influence cap** (approved). Let `cap_f` be half the iso distance to the nearest other face centre (oval-bbox centres of the listed faces and of the obstacles, §3.6).
  - The cap is a **displacement budget**, the 瘦臉 limit's own construction (`reshape.ts:186-205, 267-278`), not a multiplicative window. With `t = cap_f − |tc − c_f|_iso`, the budget is 0 for `t ≤ 0`, eases in over `PROTECT_RAMP·cap_f` and then rises with slope `PROTECT_SLOPE`; the face's whole displacement keeps its direction, and its length becomes the smooth minimum of its length and the budget. The influence is therefore 0 beyond `cap_f`, the features near the centre are untouched, and what the cap adds to the Jacobian is bounded as for the limit (det J ≥ 1 − PROTECT_SLOPE − 0.02). A window `1 − smoothstep(0.6·cap_f, cap_f, r)` would add `d ⊗ ∇w` (up to about −0.45 of det J at one face width, where the cheek moves most) and jump where it switched off.
  - A face with no neighbour has no cap, so the one-face result is bit-identical to v0.3. In the camera a neighbour's distance is divided by its presence easer, so caps change over 150 ms when a face enters or leaves the view.
  - A CPU-port sweep (centre distances 0.6–2.6 face widths, three directions, two and three faces, both ends of the bidirectional items, two yaws) keeps `min det J ≥ MIN_DET` (0.35) and checks that eyes, nose and mouth keep ≥ 0.9 of their effect at ≥ 1.2 face widths.
- **Protect array:** a `sampler2DArray` of R16F (filterable in WebGL2), with one layer per face: the photo grid (≤ 256 edge) for a single face, a 128² window around the face when there are ≥ 2, so small faces keep enough texels per face width. It is sampled with a dynamic layer index and `textureLod` (the call is in non-uniform control flow). The index is a texture coordinate, so the rule that sampler arrays need constant indices does not apply.
- **Makeup:** one copy, then N mesh draws of 176 triangles each. Mesh fragments without makeup are discarded, so where faces overlap, the last face wins only where both have makeup.
- **Composite** reads per-pixel strengths from N (the warped M). Its uniform count does not depend on N faces.
- **Texture units:**
  - composite: 0–7 as today, 8 look LUT in the 調節 program variant (9 units; the WebGL2 minimum is 16). Step 4 adds no composite unit (step-4 spec A6);
  - P2: src, body, protect array, face table, liquify (5 units).
- **Fallback ladder** (set from Phase 0, §6). `MAX_RENDER_FACES` is a compile-time constant of 6.
  - If reshape at N = 6 costs more than 8 ms at 2048 on the test iPhone, the editor cap drops to 4, then 2.
  - If live at 3 faces cannot hold 24 fps at tier H, the live cap drops to 2, then 1. At 1 the camera's 選臉 is hidden and behaves as v0.3.
  - Both face-table carriers are written (the same layout; 6 × 96 × 16 B = 9.2 KB fits the guaranteed 16 KB of a UBO). Phase 0 ships the faster one on the test iPhone, and a failed precision probe (RGBA32F `texelFetch` on iOS Safari) forces the UBO.

### 4.4 New stages, in brief (each sub-spec owns the exact math)

**調節 (step 2).** Values are in shader space: `s = (v − 0.5)·2` for bidirectional items, `v` for one-way items.

| Item | Operation |
|---|---|
| 曝光 | ±1 EV gain in linear light |
| 亮度 | Midtone curve on encoded luma |
| 對比 | S-curve about 0.5 |
| 高光 / 陰影 | Luminance-masked curves |
| 色溫 / 色調 | White-balance gains in linear RGB |
| 飽和 | Mix with Rec. 709 luma |
| 鮮艷度 | Saturation weighted by (1 − chroma), with a skin hue guard |
| 褪色 | Black lift to 0.16·v (褪色 100 lifts black to 41/255), white lowered by 0.04·v, chroma × (1 − 0.1·v) (step-2 spec §4.2) |
| 暗角 | Aspect-corrected radial falloff in V |
| 顆粒 | Monochrome hash noise on absolute output pixels. Cell = `fullShortEdge/1080` px; amplitude peaks in the midtones; the noise does not depend on the tile. |

**一鍵質感 (step 2).** Each look's LUT is generated by `scripts/gen-luts.mjs` as `look_<id>.png`: 512², 64³ layout, original work (`gen-luts.mjs` header). Starting offsets at 程度 100, in display units:

**膚質 (step 4)** runs in O before makeup (§4.2). Every tool is gated by a region mask drawn from the landmarks in P0 (R or Q) and by colour guards, not by the skin ramp `p`, which fades out on darker skin (step-4 spec §4.2–4.5).

| Tool | Operation |
|---|---|
| 勻膚 | Pulls the mid-band chroma toward a low-pass skin reference (the cached tone field); the high frequencies are kept |
| 膚色 | Hue and white-balance shift inside the skin region, signed |
| 黑眼圈 | Under-eye region: luminance lift and desaturation toward the cheek tone |
| 法令紋 | Nasolabial band: lifts dark low-frequency residue |
| 白牙 | Inner-mouth polygon: yellow desaturation and lift, only on pixels that look like teeth (high L, low chroma) |
| 亮眼 | Iris and sclera: brightness, local contrast and slight sharpening |
| 祛痘 (P0b) | Each spot quad copies a donor patch from beside the spot (stored offset) and adds a harmonic membrane fitted to the ring, the healing-brush construction, so the skin's own grain is kept |

**Makeup (step 5)** is procedural. Each item is a strip or quad in landmark space (pts111, ext, `Face.iris`, `Face.lids`) with per-vertex feather alpha and fixed-function multiply, screen or over blending (soft-light would need the destination colour, a feedback loop):
- 睫毛 uses a stroke texture that `gen-makeup.mjs` generates from math (our own work);
- 美瞳 uses `Face.iris`; the eye items follow MediaPipe's dense lid contour `Face.lids`.

No bitmap from GPUPixel, PixelFree or any other SDK is added. 美瞳 (`EAR < 0.15 → 0`) and 睫毛 fade with an eye-aspect-ratio blink gate; 眼影, 眼線 and 臥蠶 sit on the lid and stay on closed eyes (step-5 spec §4.9, §11 Q4).

**Warps (step 5)** reuse today's primitives (`curveWarp`, `shiftAround`; `reshape.ts:239-265`) where they cannot fold, plus two new ones (step-5 spec §4.2):
- 鼻翼 is a pair of opposed `shiftAround`s at the alar points (the 眼距 construction);
- 山根 is `squeezeAxis`, a squeeze of the band between the inner eye corners, which never moves an eye;
- 嘴高 is `shiftEllipse` at `pts111[106]`, a flat-topped elliptical translate that moves the whole mouth;
- 太陽穴 and 下頜線 are contour curve warps, bounded by the protect array;
- 髮際線 is `shiftEllipse` at `ext[0]`.

Split items are stored landmark-sided: `values` drives the GPUPixel-left half of the face and `right` the other half; the midline point p16 takes the mean. The 左／右 labels follow the screen (§11 Q6), mapped per face through the view, so a 翻轉 swaps the labels, never the stored values (step-5 spec §3.4).

**Liquify (step 6).** Strokes are rasterized on the CPU (`src/edit/liquify.ts`) into an O-space backward field (RG16F, long edge 512).
- **Push:** each stamp **composes** with the field, `L' = B + L∘(id + B)` with `B = −g·w(x)·Δ` (BR:138), so it pushes what is on screen; a plain sum of stamps folds on long strokes. `w` is the compact profile `(1 − r²/R²)³` of the brush radius and Δ the finger delta in O. Stamps are spaced at radius/4.
- **Restore:** multiplies the field by `1 − w(x)·strength`.
- Changes are incremental: copy-on-write tile patches record what each stroke overwrote, so undo copies them back; a full rebuild runs only past the patch budget and on load.
- A `fieldMinJacobian` check (`field.ts:167`) guards **each stamp**, push and restore alike: a stamp that would go below det 0.2 is scaled back by bisection. Replay runs the same guard, so preview, commit and replay match (the step-6 spec explains the 0.2 floor).

### 4.5 Multi-person 美體 and per-person protection

- **One field per photo:**

  ```

  ```

  - `L_p` is person p's local field from its own measure and its own params.
  - `B_p` makes the *other* persons protected zones as a magnitude budget: the length of `L_p` becomes the smooth minimum of its length and 0.45 × the distance to the union of the other persons' masks (0 inside them). Like the 瘦臉 limit, it adds at most about 0.45 to the Jacobian, whatever the gap between the persons. A fixed feather would fold next to a close neighbour, where the relax keeps the original field (narrow gaps, `field.ts:218-224`).
  - 背景保護 on: each `L_p` is weighted by its own mask (`protectWeights`). The background relax (`relaxBackground`, `relax.ts:57`) runs **once** on the sum, with every person's texels held fixed.
  - The fold guard `fieldMinJacobian ≥ MIN_DET` bisects a per-person `λ_p` on each budgeted term first (as today, `field.ts:148-159`), so a drag on one person never weakens another. The global `Λ` over the sum is a last resort; it is reported and expected to stay 1.
  - Row bands stay global (`增高`, and `長腿` measured on `legsAnchor`).
- **Which persons count:** only persons with a body and any non-neutral local item contribute. With one person this reduces to today's builder exactly.
- **Rebuilds:** `BodyFieldMemo` (`editorModel.ts:235`) keys on the body items of every person, the bands, `bodyProtect`, `legsAnchor` and `upQuarter` (§3.5). Drafts rebuild only the person being dragged and reuse the others' cached L_p.
- **瘦臉 limit per face:** `buildFaceProtect(face, own, others)`.
  - The own region is the person's pose mask when the pair exists. Otherwise it is the selfie mask ∩ the face's Voronoi cell (by iso distance between face centres), connected to the oval (`faceProtect.ts:107-145`).
  - Texels of other persons count as infinitely far, so the budget there is 0.
  - `FaceProtectSource` (`faceProtectModel.ts:150`) becomes a `Map<faceId, …>`.
  - The request flag `HistoryEntry.faceProtect` stays photo-level: one request covers every face with a contour edit.

### 4.6 Full-resolution export (step 3)

- **Source.** On import, when the oriented long edge from `probeSize` is above the working edge, the picked file is kept as `HistoryEntry.source`, as it is, if two conditions hold: it is ≤ 30 MB, and `navigator.storage.estimate()` shows at least 3× its size free. Otherwise there is no source, and the 原始 export uses the working copy with the note 「此照片只保留了 2048 解析度」. Camera shots need no source: the frame is ≤ 1920 and is already the `original`.
- **Export size.** In `full` mode the long edge is `min(source long edge, FULL_EXPORT_MAX_EDGE = 4096)`. `standard` mode is the working size (2048, or 1440 on tier L), untiled, and is today's path (`Editor.tsx:615-620`; step-3 spec D6).
  - `full` is unavailable when the effective tier is L, when the crash breadcrumb is set, or when Phase 0 marks the device class as too small.
  - The breadcrumb `meiyan.exportGuard.v1` is written before a full export and cleared afterwards. If it is found at launch, `meiyan.exportCap.v1` is set to 2048 and a toast is shown once.
- **Tiles.** Output tiles are the largest `TILE ∈ {2048, 1024, 512, 256}` V-pixels whose worst tile keeps the GL buffers within a 40 MB budget; 1024 is the expected default (step-3 spec D9). For each tile, the planner computes the O-space source window as the bbox of Geo⁻¹(tile ⊕ kernel apron), plus a displacement bound, plus 4 px:
  - the displacement bound is analytic, never sampled (step-3 spec D7): the liquify model's exact `maxDisp` over the tile's O rect (step-6 spec §4.4), plus the body field's largest texel, plus each nearby face's `displacementBound` (the sum of its active warps' largest moves); a dense CPU-port grid tests it;
  - the kernel apron is `ceil(14·k) + 2` V-pixels per side, rounded up to a multiple of 4, with `k = fullShortEdge/720` (the two mean passes act on different axes, and the sharpen reach lies inside, step-3 spec D11);
  - each spot whose quad meets the window grows the window around that spot and its donor, because the heal runs in O (step-4 spec A5); the tone field is one global texture built at working resolution from `toneSource`, so it needs no apron.

  Each tile:
  1. crops the decoded bitmap with `createImageBitmap(full, sx, sy, sw, sh)`;
  2. renders with `sourceWindow` and `output.tile`;
  3. reads the pixels back;
  4. is drawn into one output `OffscreenCanvas` at its offset.

  The output is then encoded as JPEG (q 0.95 in `full` mode, 0.92 in `standard`) or PNG. All passes take a window uniform `uWin` (buffer uv → O or V). The working-resolution preview uses the identity window, so its pixels do not change.
- **Memory budget** for 12 MP: decoded bitmap 48.8 MB + output canvas 48.8 MB + GL tile buffers ≈ 6 × (1024 + apron)² × 4 B ≈ 40 MB, about 140 MB in total. Phase 0 verifies this on iPhone.
- **Share window.** If the export took more than 4 s from the tap, the pill turns into 「分享」 and the toast 「已準備好，點一下分享」 appears. The next tap shares synchronously (`exporter.ts` saveFile rules).
- **Failure** (an exception, a context loss, or an aborted decode): fall back to `standard` once, with the toast 「已改用標準解析度輸出」.

- **No IndexedDB schema bump:** the database `meiyan`, `DB_VERSION` 1, store `edits` and keyPath `id` stay as they are (`history.ts:15-18`). The new fields are plain properties. `addEntry`, `updateEntry` and `normalizeEntry` copy them explicitly (`history.ts:30-44, 77-92, 160-180`).

## 7. Error and edge cases

| Case | Handling |
|---|---|
| More faces than the cap / faces too small | Keep the largest; show the over-cap or too-small toast once. Dropped faces get no effect (mask 0). |
| A face with no pose pair, or a pose with no face | Face-only or body-only person; tabs that do not apply show the §2.2 notes |
| Overlapping or adjacent faces | Influence cap (§4.3); protect zones (§4.5); makeup: last face wins |
| A photo with no face | Global skin from the primary person (§3.3); 美型 and 美妝 notes as today (`Editor.tsx:789-797`) |
| Tracker recovering during the first detection | As today (`RedetectBudget`, `editorModel.ts:34`); no cache is written until there is a definite answer |
| Engine swap or context loss | The session is rebuilt from the cached faces (`still.ts:63-67` generalized); the selection is kept |
| A rotation that leaves no face | One re-detect in the new up-frame U when normal mode shows it (§3.5); when it finds faces, the `p0` params go to the new primary person through `rebase` |
| Undo across a detection that added persons | `rebase` injects the new persons into every state, so they never disappear on undo |
| 全部 with mixed applicability | Writes only the persons the item applies to; the 「各人不同」 caption reflects those persons only |
| Camera: selected face lost, or a flip, or a ratio change | Fade out, search for 1 s, then fall back to the largest face; `resetSession` clears everything |
| Camera: front camera mirrored | Taps and the seed are un-mirrored or mirrored exactly as the saved image is (§3.7) |
| Crop smaller than useful | Minimum crop is 5 % of each E dimension and ≥ 64 output px |
| Straighten with a crop | The crop is constrained inside the rotated image (`cropConstrain`), shrinking about its centre |
| Spot or stroke on a region later cropped away | Kept (O-space). Invisible in the view but restored when the crop is undone. |
| Full export: OOM, context loss, slow share | Fall back to `standard` once; crash breadcrumb; two-tap share (§4.6) |
| Storage quota at the source write | No source kept; note in Settings and at export |
| A v0.3 entry reopened on tier L (1440 decode) | Normalized coordinates make the cache valid at any decode size |
| Basic mode (no tracker) | No face detection; `faceScans = []`; photo-level tools and 美體 work |
